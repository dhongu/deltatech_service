Overview

Equipment billed by use, such as printers charged per page, is invoiced on meter reading differences. This module links machines, meters and contracts and bases billing on the readings.

  • Installation and removal
    The Install, Add to Agreement and Remove from Agreement buttons open wizards that record readings, set the Status and log it in History Equipment/Agreement. Adding creates contract lines from meter templates; removal prepares the chosen Period's consumption and deactivates the equipment's lines.
  • Billing from readings
    The Billing Preparation wizard sets each metered line's consumption quantity to the summed differences of readings not yet in a consumption, from the later of the agreement and installation dates to the period end. A reading in a consumption cannot be deleted.
  • Readings control
    For agreement types with Requires readings for billing, billing preparation refuses contracts without Readings done, unless the user is in Can bill without meter readings; scheduled billing skips them, and billing clears the tick.
  • Invoice annex
    The Export meters XLS button on a customer invoice downloads the billed meters with equipment, serial, previous and read values.
  • Equipment from serials
    A new serial number of a product whose category has Equipment type required creates the equipment.

It builds on Services Agreement and Services Equipment Base. Service managers run the operations; service users enter readings.

Versions

20.0.1.1.18 (2026-11-11)

  • Apps Store page: a fuller description (what the module does, the problem it solves, its main functions, dependencies and limits). No change in behavior.

20.0.1.1.17 (2026-10-15)

  • Searching an equipment by serial number or EAN code ignored the domain of the field and the result limit, and could list the same equipment twice. The serial number and the EAN code are now searched together with the name (also from the search bar), so the domain and the limit apply to all results.
  • The equipment dropdown shows address, emplacement and serial number in a second, dimmed column; the plain name (reference/address/emplacement/serial) used on invoice lines is unchanged.
  • Automatic billing requires Readings done only for agreement types with Requires readings for billing, like the manual billing preparation; agreements without meters are billed again on their date (EQUIPMENT-004).
  • Readings done is cleared after the agreement is billed, for the types that require readings, so the next period is not billed on the previous readings (EQUIPMENT-005).

20.0.1.1.16 (2026-10-04)

  • New stock.move._get_service_signed_value(): the valuation (stock.move.value) of the done moves, negative for deliveries and positive for returns, as the former valuation layers were; non-valued moves count as zero. The equipment cost refresh uses it, and so does the agreement cost update of deltatech_service_consumable (EQUIPMENT-002). Port of 19.0.1.1.16 (dhongu/deltatech_service#104). Adapted for 20.0: Odoo 20 already stores stock.move.value with the sign (negative for outgoing moves), so the helper only sums the done moves instead of applying the sign from is_out / is_in; the removed stock_valuation_layer_ids and the guard on stock.picking.equipment_id were already handled on 20.0; the test uses ir.config_parameter.set_str().

20.0.1.1.15 (2026-10-01)

  • Consumption generated from meter readings converted the meter unit to the agreement line unit with the inverse ratio (e.g. 2 dozen became 0.1667 units instead of 24). The conversion now uses the standard Odoo unit conversion; a line without a unit uses the product unit.

20.0.1.1.14 (2026-09-30)

  • Own module icon in the flat style of the other modules.

19.0.1.1.13 (2026-09-24)

  • Consultant sheet (readme/FISA_CONSULTANT.md, in Romanian) with 11 screenshots generated by tests/test_screenshots.py (runs only on request, tag fise_screenshots): installation, agreement, meter readings and consumption-based invoicing, with the known limitations.
  • Romanian translation: wrong terms corrected (e.g. Removal, Agreement Type, Meters).

19.0.1.1.12 (2026-09-23)

  • Translatable strings in code use self.env._() instead of _(), the Odoo 19 convention (pylint-odoo prefer-env-translation). The translated messages are unchanged.
